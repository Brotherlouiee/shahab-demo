# ADR-0009 — تقدم ریفکتور US-13 بر آماده‌سازی انتشار US-12

- **وضعیت:** پذیرفته‌شده با دستور صریح مالک محصول، ۲۰۲۶-۱۰-۱۳
- **دامنه:** ترتیب اجرای User Storyها و گیت‌های وابسته به محیط؛ **نه** معماری، قرارداد API، طراحی، داده یا شرایط انتشار
- **جانشین تصمیم ترتیبی:** برنامهٔ ۲۰۲۶-۱۰-۱۲ که US-13 را پس از US-12 و آخرین داستان قرار می‌داد
- **مراجع الزام‌آور:** سه قانون طلایی، `docs/SHAHAB_PROJECT_DEVELOPMENT_CANONICAL_GUIDE.md` و `docs/TASK_EXECUTION_PROTOCOL.md`

## مسئله و زمینه

طبق سند قبلی، `US-12` شامل preview/استقرار و آزمون‌های واقعی آنلاین است و `US-13` بعد از آن تعریف شده بود. مالک فعلاً به سرور آنلاین و Docker Hub دسترسی ندارد. با این وجود، ریفکتور محافظه‌کارانهٔ فرانت قابل آزمون در CI و محیط مستقل است و توقف توسعه مطلوب نیست. تسک `US-12.T04A` برای build/test دو Docker image و publish در Docker Hub نیز به‌عنوان کار انتشار ثبت شده است؛ ساخت کاندید بدون account قابل انجام است، push واقعی وابسته به account/Secrets و approval می‌ماند.

## تصمیم

1. ابتدا `US-13.T01` و زوج‌های کوچک `US-13.T02.nn → US-13.T03.nn` و سپس `US-13.T04`، بر پایهٔ baseline قبل از ریفکتور، با **صفر تغییر ظاهری/رفتاری** و آزمون تصویری، عملکردی و چهار CI.
2. سپس `US-12.T01` و `T02`، آنگاه آماده‌سازی `T03`، `T04` و بخش قابل اجرای `T04A` با کد **بعد از ریفکتور**، بدون ادعای قبولی preview/restore واقعی یا publish registry.
3. پس از این کارها جدول معوقات موجود دوباره بر اساس evidence، وابستگی، مجوز و readiness بازبینی شود. فراهم‌کردن سرور HTTPS آزمایشی و حساب Docker Hub با مالک است و هیچ اقدام ناشی از این ADR خودکار نیست.
4. پس از ایجاد امکانات، به ترتیب وابستگی‌های فنی `US-09.T081 → US-09.T07` و سایر گیت‌های باز US-10/US-11/US-12 و publish واقعی `US-12.T04A` انجام شوند؛ تنها پس از همهٔ پذیرش‌ها و approval، `US-12.T05` انتشار production و post-deploy را انجام دهد.
5. **تمایز وضعیت:** اجرا/آزمون مستقلِ یک بخش می‌تواند ثبت شود، اما تسک/داستانی که شاهد آنلاین ضروری ندارد **Done نیست**. این استثنا فقط ترتیب شروعِ کار مستقل را تغییر می‌دهد، نه معنی Done، الزام امنیت، حفظ تاریخچه داده، retention یا approval برای publish.

## نتیجه و عدم‌تغییرها

- پایان واقعی پروژه با `US-12.T05` و تمامی release/rollback/restore/security/preview gateهای بسته‌شده است؛ `US-13.T04` پایان ریفکتور پیش از انتشار است.
- هیچ UI، CSS، asset، متن، route، state، cookie، API، scoring، دادهٔ وام یا دیتابیس به‌واسطهٔ این سند تغییر نمی‌کند. ریسک اختلاف تصاویر baseline (از جمله کارت saved-loans در عرض 390px) **نباید** با دست‌کاری reference، mask، tolerance یا کاهش CI پوشانده شود.
- حساب Docker Hub هنوز موجود نیست؛ secrets فقط از طریق مدیریت امن مالک و GitHub Actions Environment و نه در Git نگهداری می‌شوند.
- یادداشت‌های قدیمی US-13 و بخش‌های تاریخ‌دار سند جامع به‌عنوان سابقه باقی می‌مانند؛ در تعارض، دستور ۲۰۲۶-۱۰-۱۳ و بخش جدید canonical حاکم‌اند.
- سند تداوم مطابق پروتکل فقط در پایان واقعی یک User Story یا درخواست مستقل صریح مالک به‌روزرسانی می‌شود؛ این ADR پایان هیچ داستان یا مجوز اجرای سرویس آنلاین نیست.

## تصمیم‌های جایگزین ردشده

- توقف همهٔ توسعه تا خرید سرور: اتلاف زمانِ کار قابل انجام مستقل از سرور.
- اعلام زودهنگام پایان US-11/US-12 یا حذف تست‌های آنلاین: خلاف قرارداد امنیت و پذیرش.
- آغاز انتشار پیش از ریفکتور و سپس ریفکتور روی نسخه منتشرشده: ناسازگار با ترتیب جدید مالک و نیاز به دوباره‌کاری release gate.


## تخصیص محدود تصمیم — ۲۰۲۶-۱۰-۱۸، PR #132

مالک آماده‌سازی US-12 را پیش از Public کردن خواست. از این تاریخ بخش‌های مستقل
T01، آماده‌سازی/بررسی‌های ممکن T02، config/طرح T03 و T04، سپس T04A.1/.2 می‌توانند
با همان شناسه‌ها و دامنه مصوب روی main فعلی آماده شوند؛ پایان US-13 شرط شروع این
آماده‌سازی محدود نیست. full gate و ممیزی نهایی روی SHA بعد از US-13، شواهد واقعی
سرور و registry، gate T05 و مجوزهای انتشار برقرارند. شکست فنی باید رفع شود؛
نبود محیط به‌صورت blocked ثبت می‌شود و فقط کار مستقل بعدی اجازه ادامه دارد.

برنامه/رجیستری/ترتیب داخلی US-13 تغییر نمی‌کند. آماده‌سازی «Done نهایی انتشار»
نیست. سایت محدود برای بررسی کاوه‌نگار و OTP خاموش، با انتشار نهایی محصول یکی نیست؛
mock در سایت عمومی فعال نمی‌شود. مجوز تغییر visibility، merge، deploy، نشر image
و ارسال واقعی SMS با این ADR صادر نشده و هیچ‌یک انجام نمی‌شود.

معوقات جدید به **همان جدول موجود سند جامع** افزوده و ردیف‌های موجود تکمیل می‌شوند؛
OTP به PR #133/US-11.T06 ارجاع دارد، نه پیاده‌سازی مجدد. وابستگی runner/CI و حساب
Docker Hub از نیاز VPS جداست. متن تاریخی بالا فقط در تعارض با شروع این آماده‌سازی
و زمان به‌روزرسانی دفتر تخصیص یافته است؛ سایر اصول آن پابرجا هستند.
