## تغییر قرارداد و تصمیمات

قرارداد به یک Skill واحد پیشنهادی `shahab-planner` با چهار رفتار `INITIAL PLAN`، `REPLAN`، `VALIDATE` و `EXPLAIN` محدود شد. سقف طراحی/ساخت/آزمون/اصلاح ابزار `60 MINUTES` است؛ زمان اجرای واقعی برنامه‌ریزی از آن جداست. تاریخچه با Git نگهداری می‌شود. موتورهای مستقل، دیتابیس/API/UI/داشبورد، گراف تکراری، سیستم نسخهٔ مستقل و سند دانش جدید از دامنهٔ MVP خارج‌اند.

حداقل برنامه شامل Week، outcome و work reference، dependency، policy، blocker تصمیم باز، effort، هزینهٔ توسعه و بهره‌برداری، token، ظرفیت، پذیرش، آزمون، وضعیت و شاهد است. UNKNOWN صفر نیست. چرخه حداکثر هفت روز، تخمین پیش از تعهد، نسبت‌های مصوب O5-09، معیار پذیرش، گیت‌های انتشار، مجوز مالک و عدم تغییر برنامهٔ committed بدون اجازه حفظ شده‌اند. تغییر اولویت به‌تنهایی دامنه یا تقدم و قرارداد را حذف نمی‌کند.

P5-D01…P5-D16 و تاریخچهٔ گزینه‌ها همچنان `OPEN / PENDING_APPROVAL` هستند؛ هیچ موردی تصویب نشده است. رجیستر اکنون آن‌ها را برای کارکرد MVP گروه‌بندی می‌کند: تعریف outcome/تخصیص بدون دوباره‌شماری (D01/D02)، ظرفیت واقعی (D03؛ نسبت O5-09 باز نیست)، مبنای مقادیر ناشناختهٔ تخمین/هزینه/توکن (D04–D06/D12)، اولویت مالک میان گزینه‌های امکان‌پذیر (D07/D08)، و تأیید فرمت خروجی Git پیش از ساخت Skill (D14).
