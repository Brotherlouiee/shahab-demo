## تهدید، مرز و محدودیت
- Origin/Fetch-Metadata راه حل بخشی از CSRF مرورگر است؛ هر mutation با کوکی فقط same-origin. bearer صریح از origin allowlist هنوز باید auth و owner را در backend پاس کند. requests بدون Origin/Fetch-Metadata برای clients nonbrowser، همچنان تنها بر اساس توکن/proof سرور قابل اجرا هستند؛ احراز مالکیت تضعیف نشده.
- CORS فقط originهای پیکربندی‌شده و معتبر HTTP(S)، بدون wildcard/credential/path؛ تنظیمات نامعتبر در startup رد می‌شود؛ methods/headers allowlist. origin نامعتبر یا cross-site بدون bearer رد می‌شود؛ Swagger same-origin باقی می‌ماند.
- ۱ MiB سقف درخواست API mutation؛ Content-Length دروغین به‌تنهایی کافی نیست، هر chunk هنگام دریافت با اندازه تجمیعی کنترل می‌شود؛ بدنهٔ بیش‌ازحد پیش از تخصیص نامحدود رد می‌شود. rate-window اصلی OTP در C موجود است و این task برای تمام APIها distributed IP rate-limit اختراع نمی‌کند؛ quota/limits proxy upstream و timeout هم باید روی host واقعی enforce شوند.
- HSTS روی HTTPS بر اساس scheme دریافتی ASGI است، نه اعتماد بی‌قید به X-Forwarded-* کلاینت. در reverse proxy باید trusted proxy headers و TLS termination/HTTPS redirect درست پیکربندی شوند. Host/TLS/provider production در این مخزن اثبات نشده‌اند، blocker دیپلوی صریح باقی می‌ماند.
- secrets در repo/log/test منتشر نمی‌شوند؛ Swagger با `persistAuthorization=false` و `validatorUrl=null` باقی است.
- provider واقعی SMS/prod credential تأمین نشده؛ mock همچنان فقط local/test و staging/production deny است. این PR نصب یا فعال‌سازی real provider نیست.
