## پیش‌پرواز و محدوده

- مبنا: مرج PR #117 و SHA `5a25d1e6938167daf3677d762fb9c92efa3cd30d`.
- رفتار پیشین: `npm run quality` شامل Ruff/Mypy/secret scanner سفارشی بود؛ در `.github/workflows/quality.yml` شغل SAST و SCA مستقل وجود نداشت. هیچ اثبات DAST روی دامنه HTTPS دارای مجوز در CI وجود نداشت.
- هدف: افزودن job مستقل SAST `bandit` و audit وابستگی‌های نصب‌شده Python / lockfile Node؛ حفظ secret scan؛ ابزار خواندنی و opt-in برای smoke محیط HTTPS مجاز؛ ثبت یافته/بلاک‌کننده، بدون bypass و بدون credentials.
- مرز: `.github/workflows/security.yml`، ابزار opt-in کوچک `scripts/authorized_staging_security_smoke.py`، آزمون سیاست/ورودی، مستندات و CHANGELOG. هیچ UI/asset/API runtime/DB/migration/score/source/config رسمی تغییر نمی‌کند.
- محیط: اسکن وابستگی در GitHub Actions روی snapshot هر PR؛ آزمون HTTPS بیرونی فقط بعد از تأیید مالک میزبان و محیط آزمایشی قابل اجراست. اجرای خودکار علیه host عمومی یا production ممنوع. تست SCA وجود advisory را اثبات می‌کند، نه exploit؛ ثابت بودن نسخه ابزار امنیتی مستقل از نسخه‌های آزاد runtime است.

## معیارهای پذیرش و رفتار در شکست

| Gate | فرمان / شاهد | سیاست |
| --- | --- | --- |
| SAST | `python -m bandit -q -r backend/app scripts -ll -ii` | آسیب‌پذیری high-severity با confidence medium+ مانع gate؛ medium با triage و صاحب/مهلت، نه سکوت |
| SCA Python | `python -m pip_audit --progress-spinner off` | وابستگی آسیب‌پذیر گزارش شود و gate شکست بخورد؛ تغییر حدسی نسخه یا ignore ممنوع |
| SCA Node | `npm audit --audit-level=high` پس از `npm ci` | high/critical شکست؛ lockfile بدون دلیل و بررسی وابستگی عوض نشود |
| Secret | `python scripts/scan_repository_secrets.py` | نشت احتمالی مانع انتشار؛ اسکن سفارشی جایگزین سرویس کامل یا تاریخ Git نیست |
| DAST محدود | `python -m scripts.authorized_staging_security_smoke --authorized-test-origin https://HOST-APPROVED` | تنها origin دارای مجوز مالک؛ بدون credential، فقط GET، TLS معتبر، بدون redirect و حداکثر ۴ درخواست؛ 200/401/404 و cache/HSTS/nosniff؛ بدون محیط تست اجرا نشده، نه pass |

چهار CI موجود quality/PostgreSQL/two-browser حفظ می‌شوند. CI روی SHA آخر، job امنیتی را جدا باید تأیید کند.

## یافته‌های باز و خطرها

- production/staging HTTPS و ارائه‌دهنده SMS واقعی هنوز provision نشده؛ **DAST آنلاین اجرا نشده و gate انتشار باز است**. مجوز محیط، میزبان HTTPS، credential تست مستقل و کنترل دسترسی باید قبل از آزمون واقعی مشخص باشند. هر ادعای DAST روی localhost/CI disposable کافی نیست.
- `pyproject.toml` وابستگی‌های runtime را به بازهٔ نسخه تعریف می‌کند و Python lockfile ثابت ندارد؛ audit محیط نصب‌شده به معنی SBOM بازتولیدپذیر تمام انتشارها نیست. ایجاد lock و بازبینی سیاست نسخه، scope و ADR مستقل می‌طلبد.
- risk و license policy برای وابستگی‌ها باید همراه شواهد و مالک تصمیم بررسی شوند؛ `npm audit` license policy را enforce نمی‌کند. هیچ audit پنهان و یافتهٔ medium بدون owner/deadline پذیرفته نمی‌شود.
- Python/Node advisory feeds، اینترنت Actions و rate-limit منبع خارجی هستند؛ outage باید failure/blocker ثبت شود، نه silent skip.
- credential و PII در log/CI artifact نباید قرار گیرند. داده آزمون فقط مصنوعی است؛ SAST/SCA بدون ارسال source به SaaS شخص ثالث انجام می‌شوند.
- نه تست restore، نه SAST/SCA و نه DAST خواندنی به‌تنهایی مجوز production نمی‌دهند: US-11.T04/T05، T081/T07 و US-12 gate مستقل دارند. ادامهٔ threat model مطابق سند مرجع؛ سند تداوم تنها پایان user story.
- زمان فعال تحلیل/کدنویسی/CI در این نشست ساعت‌سنج معتبر ندارد؛ زمان دقیق ادعا نمی‌شود و رخداد Git را duration فرض نمی‌کنیم.
