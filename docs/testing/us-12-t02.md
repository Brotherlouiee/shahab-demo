- quality فقط ۱۳ فایل از ۱۵ فایل tests/unit را نام می‌برد؛ loan-details-api و vite-proxy اجرا نمی‌شدند. `npm run test:unit` با discovery تمام `*.test.mjs` همان پوشه را اجرا می‌کند؛ فرمان‌های جداگانه برای توسعه باقی‌اند.
- تست dedupe جزئیات با import مستقیم Node به import.meta.env دسترسی نداشت. اکنون همان source بدون تغییر با SSR transform واقعی Vite بارگذاری و server در finally بسته می‌شود؛ HMR لازم نیست.
- local-fullstack-live در suite عمومیِ بدون API/DB skip می‌شد و قبل از OTP/فرم فعلی، کلاس‌های قدیمی و دکمه «توضیح نتیجه» را فرض می‌کرد. همان هدف به `tests/profile-live/fullstack-recommendation.spec.mjs` منتقل شد: fixture رسمی/تکرارپذیر در DB موقت، فرم و OTP فعلی، درخواست واقعی، سه partition، شرایط همان loan version، مقایسه و نمایش صریح غیرفعال‌بودن provider خارجی. هیچ response شبکه mock نمی‌شود.
- assertionهای selector/متن حذف‌شده با معیار جاری قوی‌تر جایگزین شدند: همه answerIdهای canonical، یک POST توصیه با body فقط sessionId، تعداد و ترتیب server-owned، needsReview بدون score، نبود fan-out جزئیات و عدم rescoring پس از Back. UI/فرمول برای سازگارشدن با تست تغییر نمی‌کند.
- screenshotهای مصنوعی از testInfo به artifact همان run می‌روند؛ evidence تاریخی Git بازنویسی نمی‌شود. بودجهٔ کلی journey همان ۶۰ ثانیه است؛ انتظار route پس از spinner همان الگوی ۷ثانیه‌ای suite موجود است.

## اجرای متمرکز و حفاظت محیط

```bash
npm run test:unit
npx playwright test --config playwright.profile-live.config.mjs tests/profile-live/fullstack-recommendation.spec.mjs
```

فرمان دوم نیازمند محیط همان job است: FastAPI، Node/Chromium، PostgreSQL مهاجرت‌یافته و `SHAHAB_ENVIRONMENT=local` و DB دقیقاً `shahab_profile_test`. fixture پیش از materialization/پاک‌کردن quota، نام DB و محیط را کنترل می‌کند. از URL/DB/volume مالک یا production استفاده نشود. این suite سرویس API و preview خودش را راه می‌اندازد؛ آن را روی پورت اشغال‌شدهٔ Compose اجرا نکنید. CI از checkout همان SHA و materializer موجود استفاده می‌کند؛ secret واقعی یا اجازهٔ ارسال SMS لازم نیست.
